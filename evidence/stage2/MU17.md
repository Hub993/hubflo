# MU17 — Universal Routing and Structured-Meaning Convergence

Source dependency: MU16 checkpoint `ed34280`.

## Implemented capability

- One non-mutating structured routing result composes the accepted Core and
  Construction Industry recognizers and selects existing business handlers.
- Converged routes cover tasks (assigned/self/urgent), notes/pinned notes,
  Orders/Deliveries, approvals/change orders, stock/material, Inspections,
  Critical-Path Delay, Reminders, Meetings, search/status, people/recipient,
  and project/phase/zone/trade context.
- Notes, pinned notes, Deliveries, and task variants continue through the
  authoritative Task handler with distinct accepted tags/subtypes.
- Explicit approval actions validate current client/project scope before the
  existing approval/rejection handler.
- Assigned-task recipient candidates are built in application orchestration
  from current authorized users and resolved through neutral Core 0/1/many
  resolution.
- Business mutations now persist canonical client identity for Tasks,
  Meetings, Inspections, Delay records, Stock records, and audit records.
- Search/status, approval, Delay numeric-ID, stock, and recipient paths enforce
  applicable client/project scope.
- Generic supplier/quantity vocabulary and ordinary fallback do not become
  false deterministic Order routes.

## Schema migration

Existing Task `client_id` is preserved and backfilled rather than removed.
Existing Inspection, Delay, and Stock tables receive backward-compatible
`client_id` columns with legacy rows assigned to client 1.

through `ConstructionIndustryModule`. The convergence layer interprets and
routes but does not duplicate lifecycle execution. Schema additions are
backward-compatible and may remain after source rollback.
